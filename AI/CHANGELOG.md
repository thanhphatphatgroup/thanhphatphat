# CHANGELOG

This file records every modification made by the AI.

The purpose is to maintain a complete history of changes during the refactoring process.

Do not manually rewrite previous records.

Always append new records to the end of this file.

---

# CHANGELOG FORMAT

Each entry must follow this format.

Date:

YYYY-MM-DD

Task:

Short description.

Files Modified:

- file1
- file2

Summary:

- Item 1
- Item 2
- Item 3

Verification:

[✓] Layout unchanged

[✓] Visual appearance unchanged

[✓] Classes unchanged

[✓] IDs unchanged

[✓] JavaScript unchanged

[✓] CSS selectors unchanged

Notes:

Optional notes.

------------------------------------------------------------

# EXAMPLE

Date:

2026-07-13

Task:

Refactor index.html

Files Modified:

- index.html

Summary:

- Fixed indentation.
- Grouped related HTML.
- Added section comments.
- Removed unnecessary blank lines.

Verification:

[✓] Layout unchanged

[✓] Visual appearance unchanged

[✓] Classes unchanged

[✓] IDs unchanged

[✓] JavaScript unchanged

[✓] CSS selectors unchanged

Notes:

No functional changes.

------------------------------------------------------------

# RULES

Always append.

Never overwrite previous history.

Never delete previous entries.

Never modify previous records.

Be concise.

Be factual.

Do not exaggerate.

Do not claim verification that was not actually performed.

If verification was not performed, explicitly state that it still needs review.

---

# PHILOSOPHY

A good changelog explains:

What changed.

Why it changed.

What was verified.

What still requires verification.

The changelog is part of the project documentation.
